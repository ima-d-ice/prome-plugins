Core Concepts

This page documents the core concepts of the system. Each section below describes a single concept in depth, starting from the most fundamental definitions and building up to advanced usage patterns.

Architecture Overview

The system is organized into layers. Each layer has a clearly defined responsibility, and dependencies always point downward, which keeps the design comprehensible and resistant to accidental coupling.

The Storage Layer

The storage layer persists documents and exposes a narrow query interface. It knows nothing about rendering, scheduling, or transport concerns, which makes it straightforward to swap backends when requirements change.

The Rendering Layer

The rendering layer turns stored documents into presentation output. It consumes a stable intermediate representation, so new output formats can be added without touching storage or ingestion code paths.

Inline Elements

Inline elements carry semantic meaning inside a line of text. They are handled by dedicated visitors that preserve nesting and never reorder content, which keeps generated output faithful to the source.

Block Elements

Block elements define the vertical rhythm of the document. Each block is processed independently and in source order, which guarantees a predictable reading experience even for deeply nested structures.

Lifecycle

Documents move through a well-defined lifecycle from ingestion to archival. Hooks are available at every stage so integrations can observe or modify documents without forking the pipeline.

Ingestion

Ingestion validates the incoming document, assigns stable identifiers, and records provenance metadata. Invalid documents are rejected with precise error messages that callers can surface directly to users.

Archival

Archival moves expired documents to cold storage while retaining an index entry. Retrieval from the archive is slower but lossless, and archived documents remain searchable for compliance audits.

Configuration

All configuration is explicit and versioned alongside the code. Defaults are chosen to be safe, and every override is validated at startup so misconfiguration fails fast rather than silently degrading.
